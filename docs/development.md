# 개발규칙

## 영역
features/<기능>/은 담당자의 코드·템플릿·CSS·JS·프롬프트·기준 데이터 영역.
common/, app.py, templates/base.html, static/ 공통 영역은 사전 합의 후 수정.
루트 CLAUDE.md 한 개와 기능별 feature_spec.md를 사용한다. 개인별 규칙 복제 금지.

## 구현 원칙
- routes.py는 요청/응답, service.py는 기능 처리. 실제 연결은 기능 개발 단계에서 구현.
- AI는 common/ai_client.py로 서버에서만 호출. 키는 환경변수로 주입하고 프런트에 전달하지 않음.
- 시장 증감률·평균단가는 코드 계산. AI는 제공 근거의 요약·해석 담당.
- 사용자 입력/출력은 서버 DB·디스크 로그·브라우저 영구 저장소에 보관하지 않음.
- 파일은 가능하면 메모리 처리. 필요시 요청별 임시 디렉터리를 생성하고 성공/실패 모두 finally에서 삭제. 브라우저 종료 알림에 정리 책임을 의존하지 않음.
- 탭 상태는 공통 shell의 메모리에 기능별로 격리. 재방문에 생성 API를 다시 호출하지 않음.
- 사용자 자료를 localStorage/sessionStorage/IndexedDB에 저장하지 않음.
- 다운로드된 파일의 실제 저장 성공은 브라우저에서 확정하기 어려움. 다운로드 요청 상태와 사용자 안내를 구분.
- 미다운로드 생성 결과나 작성 중 입력이 있을 때 beforeunload 기반 경고 설계. 브라우저에 따라 경고가 제한될 수 있고 사용자 지정 문구를 보장하지 않음.
- 내부 탭 이동에는 경고하지 않으며 상태를 유지. 파일 처리 중 중복 실행 방지와 오류 후 재시도 고려.
- 업로드 용량·형식·API 시간 제한은 구현 전에 정하고 명세에 기록.
- 테스트는 변경한 기능과 실제 실패 위험에 맞춰 수행. 미실행 항목 명시.
- 패키지 변경 시 requirements.txt, 환경변수 변경 시 .env.example 갱신.
