## 2. 실제 1회 테스트 계획 (담당자 승인 후)

범위
- 첫 실행은 **사례 A 1건, OpenAI 호출 최대 1회**. 서비스 화면에서 '검수 실행'을 한 번만 누른다.
- 자동 재시도 없음(공통 SDK 재시도 0, 기능도 재시도 없음). 실패해도 추가 호출 없이 멈추고 기록한 뒤 담당자가 다음 실행을 정한다.
- B·C는 A 결과를 검토한 뒤 별도 승인으로 진행한다.

담당자가 실행 전에 정할 것
- 모델: `OPENAI_MODEL` 값. 공통 초기 후보는 gpt-5.4-mini지만 **미확정**. 새 모델로 바꾸거나 출력 상한(4,096토큰)을 올리지 않는다.
- 키: 개인 키인지 팀 키인지, 누구의 과금인지. 키는 실행하는 셸에만 설정하고 화면·기록·대화에 붙여 넣지 않는다.
- 비용 상한: 1회 실행에 허용할 금액. 공급자 대시보드의 사용 한도 설정 여부.

공식 출처 요청(검수 1회당 자동)
- CDC(Planalto)만 robots.txt + 본문 최대 2요청, 요청당 10초·전체 30초, 1건 5,000,000바이트 이하, 재시도 없음.
- CONAR 웹·PDF는 이용 허가 미확인으로 보류(요청 0).
- **주의(2026-10-26 확인)**: 키·모델이 없어도 공식 출처 확인이 먼저 실행된 뒤 AI_CONFIG_MISSING으로 끝난다(외부 차단 모의에서 Planalto 가짜 페이지 2요청 확인). 실행 전에 같은 셸에서 두 환경변수가 설정됐는지 확인한다. 순서 보완은 후속 작업.
- Planalto 이용약관은 아직 확인하지 않았다(기존 기록). 실제 조회 전 담당자 확인이 필요하다.
- 실제 실행 시 저장소의 `features/green_claim/data/criteria_state/check_state.json`과(변경 감지 시) `criteria_work/detected/`에 확인 상태가 기록된다. 사용자 문구는 없고 Git 제외 폴더다.

요청 크기(2026-10-26 로컬 계산, 모델 호출 없음, 사례 A)
- instructions(claim_review_v1.md): 2,044자 / 4,134바이트
- input_text(기준 24개 + 문구 JSON): 47,193자 / 66,536바이트(기준 부분 46,878자)
- 결과 스키마(JSON Schema): 약 2,530자
- 토큰 수는 토크나이저 없이 계산하지 않았다(추정하지 않음). 실제 값은 응답 사용량으로 확인한다.

토큰·비용 확인 방법
- 이 기능의 검수 응답에는 토큰 사용량이 없다(공통 함수 결과의 usage를 화면에 보내지 않음). 실행 직후 공급자 대시보드의 사용량(해당 시각·모델)을 담당자가 확인해 기록한다.
- 요금(공식 가격표 https://developers.openai.com/api/docs/pricing, 2026-10-26 조회): gpt-5.4-mini Standard 1M 토큰당 입력 $0.75 · 캐시 입력 $0.075 · 출력 $4.50.
  비용 = 입력 토큰 × 0.75 / 1,000,000 + 출력 토큰 × 4.50 / 1,000,000(달러). 출력은 상한 4,096토큰이라 최대 약 $0.0184이고, 입력 토큰은 미측정이라 총액을 미리 쓰지 않는다.
  실제 응답 모델(스냅샷 이름)·적용 요금 등급이 다르면 그 가격표 행을 다시 확인한다.

실행 순서(짧게)
1. 담당자가 모델·키·비용 상한·Planalto 확인을 정한다.
2. 실행 셸에 `OPENAI_API_KEY`·`OPENAI_MODEL`을 설정하고 서버를 시작한다(README 실행 방법).
3. 문구 직접 입력에 사례 A를 붙여넣고 '검수 실행'을 한 번 누른다(최대 100초 대기).
4. 결과 화면에서 위 확인표 A 열을 채우고, 응답의 모델·기준 확인 상태·경고를 적는다.
5. 'PDF 다운로드'를 누른다(추가 AI·공식 조회 없음). PDF와 화면을 비교: 원문·R 번호·조치·구절·근거 ID·기준 버전·해시·확인 상태·경고가 같은지, 한글·포르투갈어가 깨지지 않는지, 링크가 공식 주소인지.
6. 실패하면 오류 코드·안내만 기록하고 다시 누르지 않는다.
7. 공급자 대시보드에서 토큰·비용을 확인해 기록한다.

기록 원칙
- 실제 실행 결과는 개인 기록(prompt_log.md의 service_prompt_experiment, validation.md)과 experiments/의 실험 JSON으로 남긴다. 가상 사례 문구라 저장해도 되며 키·비밀값은 남기지 않는다.
- 서비스 사용자 자료(실제 홍보물·사용자 응답·PDF)는 저장하지 않는다. 실험 기록은 개발용 가상 입력에만 해당한다.
- 모의 검증 결과를 실제 모델 실험으로 적지 않는다. 실행하지 않은 결과·비용·시간을 만들지 않는다.
