## 작성 시점
AI는 의미 있는 작업 또는 프롬프트 실험 종료 시 개인 파일에 추가 작성한다.
다른 조원의 기록 수정 금지. 기존 실험을 덮어쓰지 않고 정정 내역을 추가한다.
담당자가 검토한 후 코드와 함께 직접 커밋한다.

## 분류
development_instruction: 코딩 도구에 보낸 지시와 변경·검증.
service_prompt_experiment: 실제 서비스 모델 프롬프트의 버전별 실험.
제출 시 후자의 고도화·실패·검증 과정을 중심으로 추린다.

## prompt_log 필수 항목
실험 ID, 날짜/시간(Asia/Seoul), 작업자, 기능, 유형,
모델/설정(확인하지 못하면 미확인), 프롬프트 경로·버전,
지시 원문 또는 정확한 변경 차이, 테스트 입력/근거 자료 경로,
실제 응답 파일·중요 발췌, 발견 문제, 변경 이유,
제어 방법, 재실행 결과, 담당자 판단, 남은 한계.
프롬프트 버전 파일은 실험 후 수정하지 않고 다음 버전 생성. 키/기밀 포함 금지.

## 할루시네이션 검증
근거 없는 수치/인증, 제품 혼동, 번역 의미 변경, 출처 불일치 등을 구체적으로 기록.
출처 제한/모르면 확인 필요/수치 코드 계산/구조화 출력/사람 검수 등의 변경과 실제 결과를 연결.
JSON 출력 성공이나 규칙을 프롬프트에 넣은 것만으로 사실 정확성을 보장하지 않는다.
같은 입력으로 전후 비교하되 실행하지 않은 결과·효율 개선을 만들지 않는다.
내부 사고과정 대신 관측 가능한 응답과 근거 요약을 기록한다.

## 파일 역할
prompt_log.md: 지시/실험 고도화
validation.md: 수행 절차·기대/실제·성공/실패/미실행
sources.md: URL/문서명·기관·조회일·적용 범위
 efficiency.md: 작업 범위·사람 검수 포함 시간·실측/가정 구분
assets.md: 캡처/이미지/영상/PDF 위치와 사용권
experiments/: 공개/가상 입력 기반 실제 실험 JSON. 사용자 서비스 요청을 자동 기록하지 않음.

## 자동화 수준
현재 제공: CLAUDE.md의 작업 종료 시 로그 갱신 규칙 + 빈 양식.
미구현: scripts/run_prompt_test.py의 API 실행 및 자동 결과 저장.
향후 개발용 도구는 지정 작업자/기능/프롬프트 버전/공개 테스트 입력을 받아 실제 요청·응답·모델·시간을 고유 ID 파일에 저장하고, 기록 실패를 명시해야 한다.
생산 서비스에서는 사용자 문서/응답 기록을 비활성화한다.
외부 채팅/Higgsfield에서 실행한 내용은 자동 수집되지 않으므로 담당자가 제공한 원문·결과만 기록한다.
