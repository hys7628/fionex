# 제품소개서
담당: 유정현
상태: 기능 방향 합의(2026-10-25), 첫 버전 설계안 작성, 상세 명세 작성 중.
첫 화면(PDF 선택 + 결과 확인·수정, 개발용 예시) 구현(§17). PDF 분석 서버 API·추출 스키마·서비스 프롬프트 v1 구현(§18).
화면과 분석 API 연결 구현(§19). 모두 모의 응답·정적 검사·로직 점검만 수행했고 **브라우저 동작은 미확인**.
**실제 PDF·스캔 PDF 추출 품질 검증, 카탈로그 생성·PDF 출력은 미구현·미검증.**

표기 구분
- **[확정]** 담당자 합의 내용(2026-10-25). 공통 문서(docs/decisions.md) 반영은 공통 담당과 별도 조율.
- **[제안]** 첫 버전 설계안. 구현 전 담당자 최종 확인 필요.
- **[미정]** 구현 전에 결정할 항목. 임의 확정하지 않는다.

## 1. 목적
- [확정] 사용자: 효성티앤씨(효성TNC) 해외영업·마케팅 담당자.
- [확정] 시장: 브라질. 대상: 리젠 T2T 관련 제품소개서 **시연**.
- [확정] 한국어 제품 자료를 바탕으로 브라질 포르투갈어(pt-BR) 카탈로그를 만들고, 사람이 검토·수정한 뒤 PDF로 내려받는다.
- [확정] 출력은 **fionex 출력 양식**을 사용한다. 효성티앤씨 공식 양식이나 검증된 공식 카탈로그로 표현하지 않는다.
- [확정] 실제 보유 자료가 없으므로 추후 한국어 **더미 제품 자료**를 제작해 시연한다.
  더미 자료와 결과물에는 "시연용 가상 자료이며 공식 제품 사양이 아님"을 표시한다.

## 2. 사용자 흐름
[확정] 단계 순서

1. 한국어 자료 업로드
2. AI 자료 분석 (추출)
3. 추출 내용 확인·수정 (사람 검토)
4. 카탈로그 생성 (pt-BR)
5. 결과 검토·수정
6. PDF 다운로드

- [확정] 스캔 PDF도 지원하는 방향. 별도 OCR 엔진 대신 서버의 OpenAI API로 문서를 해석한다.
- [확정] 3단계에서 사용자가 확인하기 전에는 추출 결과를 확정 정보로 취급하지 않는다.
- [제안] 2단계(분석)와 4단계(생성)는 별도 요청·별도 버튼으로 나눈다. 4단계 입력은 원본 파일이 아니라 **사용자가 확인한 추출 결과**다(§6).

## 3. 입력
| 항목 | 구분 | 내용 |
|---|---|---|
| 한국어 제품 자료 PDF | [제안] 필수, 1개 | 텍스트 PDF와 스캔 PDF 모두 대상(스캔 지원 방향은 [확정]) |
| 제품 이미지 | [제안] 선택, JPG·PNG 최대 2장 | 별도 업로드. 원본 문서 내 이미지 자동 추출은 첫 버전 제외 |
| 바이어 회사명·담당자명 | [제안] 선택 | 입력한 경우에만 표지/거래 제안에 사용 |
| 제안 목적 | [제안] 선택 | 문구 방향 참고용. 사실 정보로 쓰지 않음 |
| 발신자 연락처 | [제안] 선택 | **사용자 제공 값만 사용**. AI가 생성·추정하지 않음 |

- [미정] 파일 크기·페이지 수·이미지 크기(해상도·용량) 상한.
- [미정] 텍스트 PDF/스캔 PDF 처리 경로 구분 여부, PDF 라이브러리, OpenAI 파일 전달 방식.
- [미정] 발신자 연락처 항목 구성(이름·이메일·전화 등)과 필수 여부.

## 4. 출력
- [확정] 출력 언어: 브라질 포르투갈어. 형식: PDF 다운로드. 서버·브라우저 영구 저장 없음.
- [확정] 결과물에 시연용 가상 자료·비공식 사양임을 표시한다.
- [제안] 고정 4페이지 카탈로그 → 2026-10-25 4페이지 구성과 생성 기준은 [확정, 담당자 합의](§20). 세부 디자인은 시안.

| 페이지 | 구성 |
|---|---|
| 1. 표지 | 제품명 · 한 줄 소개 · 대표 이미지 |
| 2. 제품 소개 | 소재 설명 · 근거 있는 특징 · 활용 예시 |
| 3. 기술 정보 | 제공된 사양 · 인증 및 증빙 확인 상태 |
| 4. 거래 제안 | 제공된 공급 조건 · 샘플 및 상담 안내 |

- [제안] 페이지별 텍스트 수정과 이미지 교체를 지원한다.
- [미정] 가상 자료 표시 문구(한국어·포르투갈어 문안)와 표시 위치(전 페이지 머리말/바닥글, 표지 등).
- [미정] 정보 부족 시 해당 출력 항목을 생략할지, "확인 필요" 문구를 유지할지.
- [미정] 긴 내용이 4페이지를 넘을 때 처리, 이미지가 없을 때의 배치.
- [미정] PDF 글꼴(포르투갈어 발음 구별 기호·한글 포함 여부), 페이지 크기, 파일명 규칙.
- [미정] fionex 로고·브랜드 요소 사용 범위와 효성티앤씨 명칭·로고 표기 여부(사용권: docs/decisions.md 미정 항목).

## 5. 첫 버전 범위와 제외 범위
포함 [제안]
- PDF 1개 + 이미지 최대 2장 입력, 선택 입력(바이어·목적·발신자 연락처)
- AI 분석 → 추출 결과 확인·수정 화면 → pt-BR 4페이지 생성 → 페이지별 텍스트 수정·이미지 교체 → PDF 다운로드

제외 [확정]
- 로그인, 영구 저장, 이력 관리, 재접속·새로고침 후 복원
- 탭 간 자동 연동(예: 시장 분석·그린 클레임 결과 자동 반영)

제외 [제안]
- 원본 문서 이미지 자동 추출
- 자유 배치, 페이지 추가, 드래그 편집
- 여러 PDF 동시 입력, PDF 외 문서 형식(DOCX·PPTX 등)

## 6. 자료 분석과 카탈로그 생성의 단계 구분 [제안]
| 단계 | 입력 | 출력 | 원칙 |
|---|---|---|---|
| 분석(추출) | 원본 PDF | 한국어 추출 항목 목록 | 원문에 있는 내용만 추출. 항목마다 근거(페이지·원문 발췌)와 판독 상태 포함. 번역·마케팅 문구 작성 없음 |
| 사용자 확인 | 추출 항목 | 확인된 항목 | 사람이 수정·삭제·추가·확인 표시. 확인 전 항목은 생성 입력으로 확정되지 않음 |
| 생성 | 확인된 항목 + 선택 입력 | pt-BR 4페이지 내용 | 확인된 항목 범위에서만 작성. 새 수치·인증·성능·공급 조건 추가 금지 |
| 결과 검토 | 생성 결과 | 수정된 결과 | 페이지별 텍스트 수정·이미지 교체 |
| PDF 출력 | 수정된 결과 | PDF 파일 | AI 호출 없음. 화면에서 검토한 내용 그대로 출력 |

- [미정] 확인하지 않은 항목이 남아 있을 때 생성을 막을지, 경고 후 허용할지(허용하더라도 확정 정보로 취급하지 않음은 [확정]).
- [미정] 원본 PDF를 생성 단계에 다시 전달할지 여부(제안은 전달하지 않음).

## 7. 추출 정보의 근거와 검토 방식 [제안]
- 추출 항목마다 표시: 항목명, 추출 값(한국어), 근거 위치(페이지), 원문 발췌, 상태.
- 상태 값(예시, 확정 아님): `추출됨(미확인)` / `확인 필요(판독 불가·불명확)` / `근거 없음` / `사용자 확인` / `사용자 수정` / `사용자 추가`.
- 숫자·단위·인증명·공급 조건은 별도 강조하고 원문 발췌를 함께 보여 사람이 대조하게 한다.
- 상태는 색과 텍스트를 함께 표시한다(docs/design_system.md 접근성 기준, `.badge`·`.notice` 사용).
- [확정] 불명확하거나 읽지 못한 내용은 "확인 필요"로 표시한다.
- 모델 출력 자체를 사실 검증 근거로 보지 않는다(AGENTS.md). 근거 발췌가 실제 원문과 일치하는지는 사람이 확인한다.
- [미정] 근거 위치 표시 단위(페이지·문단·좌표), 원문 발췌의 신뢰성 확인 방법.

## 8. 정보 출처 구분 원칙
| 구분 | 정의 | 처리 |
|---|---|---|
| 원문 근거 정보 | 업로드 문서에서 확인되고 근거가 있는 항목 | 사용자 확인 후 생성 입력으로 사용 |
| 사용자 추가 정보 | 사용자가 직접 입력·수정한 항목(바이어·연락처·수정값 등) | 사용자 제공 값으로 표시. AI가 바꾸거나 보충하지 않음 |
| 원문에 없는 정보 | 문서에서 확인되지 않은 수치·인증·성능·공급 조건 | [확정] AI가 임의로 추가하지 않음. 필요하면 "확인 필요"로 남김 |
| 가상 정보 | 시연용 더미 자료에서 온 모든 내용 | [확정] 시연용 가상 자료·비공식 사양 표시 |

- [제안] 생성 문장(소개·특징 설명)은 확인된 항목에 근거하며, 각 문장이 어느 항목에 근거하는지 내부적으로 추적한다.
- [미정] 소개 문장 수준의 일반적 표현(마케팅 문체)을 어디까지 허용할지와 검수 기준.
- [미정] 화면·PDF에 출처 구분(원문/사용자 입력)을 노출할지, 화면에서만 표시할지.

## 9. 데이터 처리·상태 유지
- [확정] 같은 페이지에서 탭 이동 시 입력·파일·결과를 유지한다(공통 shell의 `hidden` 패널 방식).
- [확정] 새로고침·페이지 이탈 후 복원하지 않는다.
- [확정] 보호할 작업이 있으면 공통 작업 상태 API(`AppShell.work`)로 이탈 경고를 요청한다.
  - [제안] 추출 결과 편집·결과 편집기처럼 자동 감지 밖 상태는 `setDraft`, 생성 결과는 `setResult`, PDF는 `downloadBlob` 사용.
- [확정] 사용자 문서와 생성 결과를 개발 기록(worklogs·experiments 등)에 저장하지 않는다.
- 공통 규칙: 파일은 가능하면 메모리 처리. 임시 파일이 필요하면 요청별 임시 디렉터리를 만들고 finally에서 삭제. 브라우저 저장소 사용 금지(docs/development.md).
- [미정] OpenAI 쪽 파일 업로드 방식을 쓰는 경우 원격 파일 삭제·보관 정책 확인.

## 10. 오류 처리와 향후 설계·검증 사례
아래는 **향후 설계 및 검증할 사례**다. 현재 처리 방식은 미구현이고 검증도 수행하지 않았다.

| 사례 | 설계 방향 [제안] | 상태 |
|---|---|---|
| 빈 파일 | 업로드 단계에서 거부, 입력 유지 후 안내 | 미설계·미검증 |
| 손상된 PDF | 열기 실패 안내, 다른 파일 선택 유도 | 미설계·미검증 |
| 암호화된 PDF | 지원하지 않음 안내(해제 기능 없음) | 미설계·미검증 |
| 회전·흐린 스캔 | 판독 불가 항목을 "확인 필요"로 표시 | 미설계·미검증 |
| 숫자·단위 판독 불가 | 값을 추정하지 않고 "확인 필요" + 원문 위치 | 미설계·미검증 |
| 제품 혼동(여러 제품·등급 혼재) | 제품 구분 표시, 대상 제품 선택 또는 확인 요청 | 미설계·미검증 |
| 근거 누락 | 근거 없는 항목을 "근거 없음"으로 표시, 생성 입력에서 제외 또는 확인 요청 | 미설계·미검증 |
| AI 호출 실패(시간 초과·응답 오류·JSON 파싱 실패·필수 필드 누락) | 입력·파일 유지, `.notice-danger` 안내, 재시도 가능 | 미설계·미검증 |
| 중복 실행 | 처리 중 버튼 `disabled`, `aria-busy`, 응답 순서 꼬임 방지 | 미설계·미검증 |
| PDF 생성 실패 | 편집 결과 유지, 재시도 가능, 서버 경로·키 비노출 | 미설계·미검증 |
| 이미지 형식·용량 오류 | 해당 이미지만 거부하고 나머지 입력 유지 | 미설계·미검증 |

- 오류 응답은 docs/data_contracts.md 권장 형식 `{"ok": false, "error": {"code", "message"}}`을 따른다.
- [미정] 오류 코드 목록, API 타임아웃·재시도 횟수·비용 한도.

## 11. 완료·검증 기준 [제안]
구현 후 다음을 실제로 확인해야 완료로 본다. 현재 모두 **미실행**.
- 더미 자료(텍스트 PDF·스캔 PDF)로 분석 → 확인 → 생성 → 수정 → PDF 다운로드 전체 흐름 동작
- 원문에 없는 수치·인증·성능·공급 조건이 결과에 추가되지 않았는지 사람이 항목별 대조
- 판독 불가 항목이 "확인 필요"로 남는지
- 사용자 미확인 항목이 확정 정보로 출력되지 않는지
- 결과 PDF에 가상 자료·비공식 사양 표시가 있는지
- pt-BR 번역 의미 변경 여부 검토(검토자·기준 [미정])
- 포르투갈어 특수문자 글꼴·페이지 나눔·이미지 품질(PDF 별도 검증, docs/design_system.md)
- 탭 이동 후 상태 유지, 새로고침 시 경고 요청·미복원, 처리 중 중복 실행 방지
- §10 오류 사례별 동작
- 사용자 문서·결과가 서버 디스크·로그·브라우저 저장소에 남지 않는지

## 12. 공통 구현 의존

## 17. 첫 화면 구현 (2026-10-25)
범위 [확정, 담당자 지시]: 한국어 PDF 선택 + 분석 결과 항목별 확인·수정. 서버 요청 없음.

PDF 선택
- PDF 1개(`multiple` 없음). 파일명·크기 표시. 스캔 PDF도 향후 분석 대상임을 안내.
- 화면 1차 확인: 미선택·빈 파일(0 bytes)·`.pdf`가 아닌 확장자. 브라우저 MIME은 판단에 쓰지 않음.
- 실제 PDF 형식·손상·암호화·용량·페이지 검사는 서버 후속 작업. 용량·페이지 상한은 [미정] 유지.
- "PDF 분석" 버튼 비활성 + "PDF 분석 연결 준비 중". 선택한 파일은 읽거나 업로드하지 않음.
  (2026-10-25 §19로 변경: 10 MiB 화면 검사 추가, 유효한 PDF 선택 시 분석 버튼 활성화, 버튼을 눌러야만 업로드)
- 이미지 업로드·바이어 입력은 이번 화면에 없음(§3 제안은 유지).

개발용 예시
- "개발용 예시 불러오기"는 PDF 없이 사용. 자동으로 불러오지 않음. 결과 상단에
  "개발용 예시입니다. 업로드한 PDF의 분석 결과가 아닙니다." 표시.
- 값: 제품명 리젠 T2T / 제품 설명 폐의류를 재활용하는 폴리에스터 섬유 / MOQ 500 kg·샘플 1 kg·납기 30일(가상 시연 조건) /
  원사 규격·탄소 저감률·인증 미제공. 효성티앤씨 공식 사양·공급 조건이 아님을 표시. 근거 위치·원문 발췌는 만들지 않음.
- 수정·확인 내용이 있으면 다시 불러오기 전에 확인 대화상자를 띄움.

확인·수정 영역
- 그룹: 기본 정보(제품명·제품 설명), 기술 사양(원사 규격·탄소 저감률), 인증 정보(인증), 공급 조건(MOQ·샘플·납기).
- 항목마다 독립 값: 값 / 제공 여부(자료 기준, 사용자가 변경 불가) / 가상 정보 여부 / 사용자 확인 여부.
  미제공과 가상은 동시에 성립할 수 있다. 예시에서 가상으로 제공된 값은 가상 표시를 해제할 수 없다.
- 값을 바꾸면 해당 항목의 사용자 확인을 해제. 미제공 항목에 값을 넣으면 "사용자 추가 정보"(문서 근거 아님),
  제공된 값을 바꾸면 "사용자 수정". 사용자 확인은 사실 검증·인증 완료가 아님.
- 화면 배치: 모든 항목에 같은 안내(사용자 확인의 의미, 수정 시 확인 해제, 가상 표시 고정, 사용자 추가 정보)는
  검토 영역 상단 "검토 방법"에 한 번만 표시. 항목에는 미제공·사용자 추가 정보 안내만 표시.
  짧은 항목은 공통 `.grid`로 검토 카드 폭이 충분할 때만 2열, 좁으면 1열. 제품 설명은 전체 폭.
- "확인 내용 적용"은 브라우저 메모리의 검토 요약만 갱신(서버 전송·저장 없음). 적용 후 다시 수정하면 안내.
- "카탈로그 생성"·"PDF 다운로드"는 비활성.

상태 유지
- 탭 이동 시 DOM 유지(공통 shell). 재진입 때 초기화·재요청 없음. 새로고침 후 복원 없음. 브라우저 저장소 미사용.
- 파일 선택은 공통 shell 입력 자동 감지, 검토 영역은 `data-work-ignore` + `AppShell.work.setDraft`(수정·확인이 있을 때만).
  예시는 다운로드할 결과가 아니므로 `setResult`를 쓰지 않음.
- 새 PDF를 선택하면 기존 검토 내용을 정리. 수정·확인 내용이 있으면 먼저 확인하고, 취소하면 이전 파일 선택으로 되돌림.
- 사용자 입력은 `textContent`·`value`로만 표시(HTML 해석 없음).

후속 [미정 유지]: 분석 API 경로·요청/응답 스키마, 모델, 파일 상한, 추출 항목 목록 확정, 근거 위치 표시 방식, 미확인 항목이 있을 때 생성 허용 여부.
(2026-10-25 갱신: 분석 API 경로·스키마·파일 상한·추출 항목 8개는 §18로 구현. 모델·근거 표시 방식·생성 허용 여부는 미정 유지.)

## 18. PDF 분석 서버 (2026-10-25, 모의 테스트만)
범위 [확정, 담당자 지시]: 추출 스키마·서비스 프롬프트·분석 서비스·API·모의 테스트. 화면 연결·실제 유료 호출 없음.
결과는 사용자가 확인하기 전의 AI 추출 초안이며 확정 제품 정보가 아니다.

요청
- `POST /api/product-brochure/analyze`, `multipart/form-data`, 파일 필드 `source_file` 정확히 1개. 다른 파일 필드는 거부, 텍스트 필드는 사용하지 않음.
- 파일 상한 10 MiB·20쪽은 공통 `config.PDF_MAX_BYTES`·`PDF_MAX_PAGES`와 `inspect_pdf` 재사용. 확장자·MIME은 판단에 쓰지 않음.
- `request.files`를 읽기 전에 이 요청에만 `max_content_length` = 10 MiB + 64 KiB(multipart 여유), `max_form_parts` = 8 적용.
  파일 스트림은 10 MiB + 1바이트까지만 읽고 초과하면 `PDF_TOO_LARGE`. 앱 전역 설정·다른 탭 오류 처리는 바꾸지 않음.
- `max_form_memory_size`는 기본값(500 KB) 유지: Werkzeug 3.1.9는 파트 종류와 무관하게 수신 버퍼에 이 값을 적용해, 작게 잡으면 파일도 413이 됨(실측).
- 업로드 저장: 영구 저장·Files API 업로드 없음. **Werkzeug는 500 KB를 넘는 파일 부분을 OS 임시 파일(SpooledTemporaryFile)로 받는다(테스트로 확인).**
  라우트 `finally`에서 `request.close()`로 닫고 Flask도 요청 종료 시 닫는다. 프로세스 비정상 종료 시 임시 파일 정리는 미검증.
- 원본 파일명은 응답·로그·공급자 요청에 넣지 않음(공급자에는 공통 고정 이름 `document.pdf`).

성공 응답 `{"ok": true, "data": {...}}`
```json
{
  "extraction_status": "unconfirmed",
  "prompt_version": "brochure_extract_v1",
  "source": {"size_bytes": 0, "page_count": 0},
  "model": "응답 모델명",
  "fields": [
    {"key": "moq", "label": "MOQ", "value": "500 kg", "status": "found|unclear|not_found", "ai_status": "found|…|null",
     "evidence": [{"page": 2, "quote": "짧은 발췌", "page_in_range": true, "check": "not_checked"}],
     "marked_virtual": true, "note": null, "server_notes": [], "confirmed": false}
  ],
  "multiple_products": false,
  "review_notes": [{"source": "server|ai", "message": "…"}]
}
```
- `fields`는 항상 8개, 순서 고정: product_name, description, yarn_spec, carbon_reduction, certification, moq, sample, lead_time(화면 key와 동일).
- 중복 key는 첫 항목에 후보 값(`candidates`)·근거를 모아 unclear, 누락 key는 value null·unclear·`ai_status` null로 채움. 알 수 없는 key는 스키마 검증 실패(`AI_OUTPUT_INVALID`).
- `confirmed`는 항상 false. found도 사용자 확인 완료가 아니다.
- `evidence`의 페이지·발췌는 **AI가 제시한 근거**이며 원문 자동 대조를 하지 않는다(`check: "not_checked"`). 검증된 근거로 표시하지 않는다.

서버 후처리
- found인데 값이 비었거나, 페이지 범위 안(1~page_count)이고 발췌가 있는 근거가 하나도 없으면 unclear로 낮춤(`ai_status`에 원래 상태 보존).
- not_found인데 값이 있으면 unclear. 범위 밖 페이지는 `page_in_range: false` + 검토 사항. 페이지 null은 유효 근거로 보지 않음.
- `marked_virtual`은 제거하지 않음(강등되어도 유지, 미제공+가상 동시 가능). `multiple_products`가 true면 서버 검토 사항 추가.
- 값·설명 2000자, 발췌 300자를 넘으면 자르고 검토 사항 추가. 근거가 있어도 사실 정확성을 보장하지 않는다.

서비스 프롬프트: `prompts/brochure_extract_v1.md`(instructions로 전달). PDF 속 명령 무시, 외부 지식·추측 금지, 없는 정보 not_found·null,
불명확·충돌·귀속 불명확은 unclear, 가상 표시 보존, 다른 제품 정보 이동·복수 제품 병합 금지, 번역·문구 생성 없음. 실제 품질 실험은 미실행.

오류 `{"ok": false, "error": {"code", "message"}}`
| code | HTTP | 경우 |
|---|---|---|
| `UPLOAD_TOO_LARGE` | 413 | 요청 전체 상한 또는 파트 수 초과 |
| `UPLOAD_FILE_MISSING` | 400 | `source_file` 없음 |
| `UPLOAD_FILENAME_MISSING` | 400 | 파일명이 빈 파트(파일 미선택) |
| `UPLOAD_MULTIPLE_FILES` | 400 | `source_file` 2개 이상 |
| `UPLOAD_UNEXPECTED_FIELD` | 400 | 다른 파일 필드 |
| `PDF_*` | 400/413 | 공통 PDF 검사(빈 파일·크기·서명·손상·암호화·0쪽·페이지 초과) |
| `AI_*` | 공통 계약 | 설정 누락·인증·호출 제한·시간 초과·거절·미완료·출력 오류 등(docs/data_contracts.md) |
| `AI_UNKNOWN_ERROR` | 500 | 예기치 않은 서버 오류(로그에는 예외 형식명만) |
- PDF 검사는 키·모델 설정 확인보다 먼저 수행(키가 없어도 잘못된 PDF는 `PDF_*`). 입력 검사 실패 시 OpenAI 요청 0회. 기능에서 추가 재시도 없음.

화면 연결 시 주의 → §19에서 구현
- 413 응답은 브라우저·서버 환경에 따라 본문 전송 중 연결이 끊겨 JSON을 받지 못할 수 있음(미검증). 화면에서도 크기를 먼저 안내.

미검증: 실제 OpenAI 호출로 프롬프트 v1 실행, 텍스트·스캔 PDF 추출 정확성, 할루시네이션 실제 발생률, 비용·소요 시간, 브라우저 업로드 동작.

## 21. pt-BR 카탈로그 문구 생성 서버 (2026-10-25, 모의 테스트만)
범위 [확정, 담당자 지시]: 입력·출력 스키마, 서비스 프롬프트 `prompts/brochure_generate_v1.md`, `POST /api/product-brochure/generate`, 모의 테스트.
**미구현**: 화면 연결, 생성 문구 수정 UI, 이미지 생성, PDF 출력. PDF 원본 재전송·분석 재실행 없음. 공통 `generate_structured` 재사용(timeout 60초·재시도 0·store=False, 추가 재시도 없음).
코드: `features/product_brochure/generation.py`, 라우트 `routes.py`.

요청(`Content-Type: application/json`, 본문 전체 ≤ 32 KiB)
```json
{"fields": [
  {"key": "product_name", "value": "regen T2T (teste)", "confirmed": true, "virtual": false, "origin": "extracted"},
  {"key": "description", "value": "…", "confirmed": true, "virtual": false, "origin": "extracted"},
  {"key": "yarn_spec", "value": "75D/36F", "confirmed": true, "virtual": true, "origin": "user_added"},
  {"key": "carbon_reduction", "value": "", "confirmed": false, "virtual": false, "origin": "extracted"},
  {"key": "certification", "value": "GRS (가상)", "confirmed": false, "virtual": false, "origin": "extracted"},
  {"key": "moq", "value": "500 kg", "confirmed": true, "virtual": true, "origin": "extracted"},
  {"key": "sample", "value": "1 kg", "confirmed": true, "virtual": true, "origin": "user_modified"},
  {"key": "lead_time", "value": "30일", "confirmed": true, "virtual": true, "origin": "extracted"}
]}
```
- `fields`는 8개 key가 각각 정확히 1번(누락 `GENERATE_MISSING_KEY`, 중복 `GENERATE_DUPLICATE_KEY`). 알 수 없는 key·필드, 다른 최상위 필드(원문 PDF·발췌·지시문·모델명 등) 거부.
- 형은 엄격: `value` 문자열, `confirmed`·`virtual` boolean(`"true"`·`1` 등 변환 없음), `origin`은 `extracted`(문서 추출)·`user_modified`·`user_added`. 위반은 `GENERATE_INVALID_INPUT`(오류 메시지에는 구조 위치만, 클라이언트가 보낸 필드명·값은 넣지 않음).
- 필수: product_name·description이 공백이 아니고 `confirmed: true`. 아니면 `GENERATE_REQUIRED_MISSING`(AI 호출 없음).
- 선택 6개: `confirmed: true`이면서 값이 있을 때만 사용. 미확인·빈 항목은 모델에 보내지 않고 `excluded`(reason `unconfirmed`/`empty`)로 반환.
- 길이 한도(구현 한도, 넘으면 자르지 않고 `GENERATE_FIELD_TOO_LONG`): product_name 120자, description 1500자, yarn_spec·certification·carbon_reduction 300자, moq·sample·lead_time 200자.
  근거: 제품명은 한 줄, 설명은 소개 문단 1~2개 분량, 규격·공급 조건은 한 항목 표기로 충분하다는 보수적 추정. 본문 32 KiB는 위 한도의 UTF-8 최대(약 12 KiB)와 JSON 여유를 합친 값. 실사용 후 조정.
- 잘못된 JSON·Content-Type은 `GENERATE_INVALID_JSON`(400), 본문 초과는 `GENERATE_REQUEST_TOO_LARGE`(413). 요청별 제한만 적용하며 앱 전역 설정·다른 기능에 영향 없음.
- 한계: 서버는 저장하지 않으므로 이전 분석 결과와 대조할 수 없다. `confirmed`·`virtual`·`origin`은 형식만 검증해 그대로 보존하며, **서버가 사용자 확인 이력을 인증하지 않는다**. 사용자 확인은 사실 검증·공식 사양 인증이 아니다.

모델 입력: 사용 항목의 `key`·한국어 라벨·값과 `details_keys`·`supply_keys`만 JSON 데이터로 전달(확인·가상·출처 메타데이터, 제외 항목은 보내지 않음). 값 안의 지시는 따르지 않도록 프롬프트에 명시.

```json
  "input_meta": {"moq": {"confirmed": true, "virtual": true, "origin": "extracted"}, …}
}
```
- 제품명은 AI가 만들지 않고 입력 표기 그대로. AI는 tagline·소개 문단·3/4쪽 라벨·값 번역만 생성(순수 텍스트, HTML·CSS 없음).
  → **2026-10-25 변경(§23)**: 표지 제품명은 원본 product_name이 아니라 사용자가 확인한 카탈로그 표시명(display_name)을 그대로 사용.
- 3·4쪽에 쓸 항목이 없으면 `items: []`, `empty: true`, `empty_message`("Informações técnicas a confirmar." / "Condições de fornecimento a confirmar."). 고정 템플릿이 빈 상태를 표시하며 AI가 내용을 늘리지 않음.
- 가상 여부는 AI 판단이 아니라 연결된 입력의 `virtual`로 서버가 계산(소개 문구도 하나라도 가상 입력을 쓰면 `virtual: true` + 고정 안내). 비공식·가상 안내 문구는 서버 고정값.
- `source_keys`는 추적 정보이며 내용의 사실 정확성을 보증하지 않는다.

출력 상한(프롬프트와 서버 검증 동일, 위반 시 잘라서 성공 처리하지 않고 `GENERATE_OUTPUT_INVALID` 502)
- tagline 140자, 소개 문단 1~2개·각 600자, 3쪽·4쪽 라벨 40자, 3쪽 값 300자, 4쪽 값 200자, 빈 문자열 불가.
- 3쪽은 사용한 details key만 각 1번(미제공 항목 추가·중복·누락·다른 쪽 항목 거부), 4쪽도 같음. `source_keys`는 비어 있지 않고 사용한 key만.
- 사용자 검토 표시(`review_flags`, 거부하지 않음): `new_number`(입력에 없는 숫자), `number_not_preserved`(입력 수치가 출력에 안 보임), `claim_term`(sustentável·ecológico·certificado·alto desempenho 등 평가 표현).
  단순 숫자·어휘 검사이며 번역 의미·사실 정확성·단위 보존을 보장하지 않는다.

오류: 공통 계약 `{"ok": false, "error": {"code", "message"}}`. 위 `GENERATE_*` + 공통 `AI_*`(설정 누락·인증·호출 제한·시간 초과·거절·미완료·출력 형식). 로그에는 오류 code만(입력 값·생성 결과 미기록).

## 22. 생성 API 화면 연결·결과 미리보기 (2026-10-25, 브라우저 미확인)
범위 [확정, 담당자 지시]: 생성 요청·결과 표시·상태 보호. **미구현**: 생성 문구 편집, PDF 다운로드, 이미지 생성·교체. 서버 API 계약(§18·§21) 변경 없음.

정책 [확정, 담당자 지시]
- 실제 PDF 분석 결과를 검토하고 "확인 내용 적용"한 정보로만 생성. **개발용 예시로는 생성하지 않음**(예시는 디자인 시안 보기만).
- 제품명·제품 설명은 값이 있고 사용자 확인 필요. 미확인·빈 선택 항목은 제외. 사용자 확인은 공식 사양·사실 검증이 아님.

적용 스냅샷
- "확인 내용 적용" 시 8개 항목의 `{key, value, confirmed, virtual, origin}` 독립 복사본과 입력 서명(값·확인·가상·origin)을 보관.
- origin: 사용자 추가(`userAdded`) → `user_added`, 사용자 수정(`userModified`) → `user_modified`, 그 외 → `extracted`. 사용자 추가 항목은 다시 고쳐도 `user_added` 유지.
- 적용 후 값·확인·가상 상태가 바뀌면 "다시 적용 필요" 표시와 생성 차단. 파일 교체·새 분석·예시 불러오기 시 입력 버전이 바뀌어 이전 스냅샷을 재사용하지 않음.

생성 버튼 활성 조건: 실제 분석 결과 + 현재 입력 버전의 적용 스냅샷 + 적용 후 변경 없음 + 제품명·설명 확인 + 서버와 같은 길이 한도 이내(넘으면 자르지 않고 안내) + 분석·생성 진행 중 아님.
버튼 아래에 비활성 이유 또는 포함·제외(미확인·빈 값) 항목을 표시.

요청·진행·실패
- 버튼 클릭 때만 `POST /api/product-brochure/generate`. 본문은 적용 스냅샷의 8개 항목(JSON Blob, Content-Type은 Blob 타입). PDF·근거 발췌 재전송 없음. 자동 생성·자동 재시도 없음.
- 분석과 생성은 서로 막음(동시 실행 없음), 중복 클릭 무시, 요청 번호로 오래된 응답 무시. 화면 대기 120초(서버 텍스트 timeout 60초보다 길게). 중단해도 서버 처리·과금 취소는 보장하지 않음(안내 문구에 명시).
- 생성 중 파일 선택·분석·예시 불러오기·검토 편집·적용 잠금, 진행 문구·spinner·검토 카드 `aria-busy`. 끝나면 복구.
- 실패 구분: 네트워크·시간 초과·413·JSON 아님(본문 미표시)·서버 오류(알려진 `GENERATE_*`·`AI_*` 코드 → 화면 고정 안내, 서버 메시지·공급자 원문 미표시)·잘못된 성공 응답. 실패 시 적용값·기존 결과 유지.
- 기존 생성 결과가 있으면 재생성 전에 교체 확인. 취소하면 요청 없음, 승인해도 성공 전에는 기존 결과 유지.

결과 미리보기
- "디자인 시안 보기"(고정 예시)와 "생성 결과 보기"(마지막 성공 결과)를 분리. 결과용 대화상자는 같은 4페이지 디자인이지만 제품 정보·공급 조건 예시 문구가 없고 데이터 칸만 있음.
- 응답 전체 검사(상태·언어·안내·사용 key·4쪽 구조·문단 1~2개·쪽별 허용 key·중복·empty 일치·source_keys·형식) 후 한 번에 반영.
- 1쪽 제품명·소개 문구, 2쪽 소개 문단, 3쪽 상세(없으면 서버 빈 상태 안내), 4쪽 공급 조건(없으면 서버 빈 상태 안내). 가상 문구·항목에 서버 고정 가상 안내, 모든 쪽 서버 고정 비공식 안내.

- 레이아웃: 2쪽 소개 문단을 이미지 바로 아래로(바닥으로 밀던 간격 제거, 시안에도 적용). 결과 2쪽은 문단 전체 폭, 합계 400자 초과 시 이미지 높이 300px·본문 크기 글자. 4쪽 값이 24자를 넘으면 큰 숫자 대신 본문 크기.

- 탭 이동 시 스냅샷·결과·경고 유지(DOM·메모리), 새로고침 후 복원 없음, 브라우저 저장소 미사용.

미검증: DOM 연결·시각 확인 전반(브라우저 도구 없음), 상한 길이 문구·빈 상세/공급의 실제 배치와 넘침, 실제 서버·OpenAI 종단 동작, 생성 품질.

## 24. 생성 결과 문구 편집·4쪽 "샘플·거래 상담" (2026-10-26)
범위 [확정, 담당자 지시]: 생성 결과 미리보기의 문구 편집(브라우저 메모리만), 4쪽 방향 정리. **미구현**: PDF 다운로드, 이미지 생성·교체, 항목 추가·삭제, 전체 번역 검토 완료 기능.
서버 API·v2 서비스 프롬프트 변경 없음. 편집·적용·되돌리기는 API를 호출하지 않음.

편집 대상(결과 대화상자의 "문구 수정", 마지막 성공한 생성 결과가 있을 때만. 고정 디자인 시안은 대상 아님)
- 1쪽 카탈로그 표시명·소개 문구, 2쪽 기존 소개 문단, 3쪽 생성된 상세 값, 4쪽 생성된 공급 조건 값. 공통 `input`/`textarea` + 명시적 라벨(contenteditable·HTML 편집기 없음).
- 제외: 항목·문단 추가/삭제, 페이지 순서, 항목명·페이지 제목, 가상·비공식 시연·AI 이미지 안내, source_keys·origin·virtual·review_flags 등 메타데이터, 미제공 정보·연락처 채우기.

상태(서로 독립 복사본)
- AI 원본(`original`, 마지막 성공 응답) / 미리보기 적용본(`current`) / 편집 중 임시 값(`editing.values`).
- "미리보기에 적용": 서버와 같은 기준(표시명 80자·한글·제어 문자, 소개 140자, 문단 600자, 3쪽 값 300자, 4쪽 값 200자, 빈 값·공백만 불가, 한글 음절·자모 불가, 줄바꿈 외 제어 문자 불가)으로 위치별 검사.
  하나라도 틀리면 아무것도 반영하지 않고 위치별 오류 표시. 자르지 않음(maxlength 미사용). pt-BR 악센트·제품명 기호 허용.
  통과하면 한 번에 반영(텍스트·값만 교체, 메타데이터·고정 안내 보존), 미리보기 다시 그리고 넘침 재검사.
- 표지 표시명 편집은 결과 적용본의 `display_name.value`와 `cover.product_name.text`를 함께 바꿈. 생성 요청용 표시명·확인 상태, 입력 스냅샷, PDF 분석·검토 값은 바꾸지 않음.
- "편집 취소"·닫기·Esc: 바뀐 임시 값이 있으면 버릴지 확인, 취소하면 편집 유지. 적용본은 그대로. 탭 이동으로 대화상자가 닫히면 확인 없이 닫고 임시 값은 보존(다시 열면 복원).
- "AI 생성 원문으로 되돌리기": 확인 후 적용본을 AI 원본 복제로 교체(편집 중이면 임시 값도 원문으로).

검토 안내(카탈로그 밖)
- AI 원본과 값이 다른 칸은 "사용자 수정 · 재검토 필요" 목록으로 표시. 사용자 수정은 사실·번역 검증 완료가 아니며, source_keys는 생성 당시 연결로 수정 문구의 정확성을 보장하지 않는다고 안내.
- 원래 review_flags(AI 생성 검토 표시)는 수정만으로 해제하지 않고 별도 목록으로 유지.
- 입력 변경 경고("현재 입력과 다를 수 있음")는 입력 서명 기준이라 출력 편집으로 사라지지 않음. 결과 카드에 수정 문구·미적용 편집 존재를 따로 안내.

재생성·보호
- 적용된 수정본이나 편집 중 값이 있으면 재생성 확인 문구에 "직접 수정한 문구까지 교체"를 명시. 취소·실패 시 원본·적용본·임시 값 유지, 성공 시에만 새 원본으로 교체하고 편집 상태 초기화.
- 결과 대화상자가 열려 있으면 패널 조작이 막혀 편집과 생성이 동시에 진행되지 않음. 생성 중에는 결과 보기 버튼 비활성.
- `setDraft` 보호 조건에 편집 중 상태 추가(OR, 다른 보호를 해제하지 않음). 브라우저 저장소·서버 저장·이력 없음, 새로고침 후 복원 없음.

4쪽 방향(고정 시안·생성 결과 공통 템플릿)
- 제목 "Amostras e condições comerciais"(머리말 "03 · Comercial"), 마무리 "Entre em contato para consultar a disponibilidade de amostras e as condições comerciais."
- 생성 결과는 실제 생성된 MOQ·샘플·납기만 표시(가상 안내 유지), 없으면 서버 빈 상태 안내 + 위 상담 문구. 연락처·제공 가능·무료·즉시 발송 약속 없음.

## 25. 카탈로그 PDF 렌더러 (2026-10-26, 서버 렌더러·모의 데이터 검증만)
범위 [확정, 담당자 지시]: ReportLab 5.1.0 서버 렌더러(`pdf_catalog.py`)와 고정 가상 데이터 검증. **미구현**: 다운로드 API·화면 버튼 연결, 동시 실행 제한·엔드포인트 타임아웃, 화면 미리보기 라벨 정렬.
팀 합의(사용자 확인): PDF 출력 도구 reportlab==5.1.0, requirements.txt는 각자 변경 후 병합 시 해결, 공통 글꼴·전체 UI 정리는 모든 기능 병합 후 별도 브랜치.

입력 계약(`parse_catalog`, 화면 `generation.current.pages`에서 문구·key·virtual만 추출하는 형태)
```
{"language": "pt-BR",
 "cover": {"product_name": {"text", "virtual"}, "tagline": {"text", "virtual"}},
 "intro": {"paragraphs": [{"text", "virtual"}] (1~2개)},
 "details": {"items": [{"key", "value", "virtual"}]},   key ⊂ yarn_spec·certification·carbon_reduction
 "supply":  {"items": [{"key", "value", "virtual"}]}}   key ⊂ moq·sample·lead_time
```
- 엄격 스키마(추가 필드·형 변환 거부): HTML·URL·파일 경로·글꼴·색·안내 문구·항목명은 받지 않음.
- 생성·편집과 같은 상한(표시명 80·소개 140·문단 600·상세 300·공급 200), 빈 값·공백만·한글(음절·자모)·제어 문자 거부(여러 줄 문구는 줄바꿈만 허용, 표시명은 줄바꿈도 불가), 쪽별 허용 key·중복 검사. 앞뒤 공백만 정리하고 값을 고치거나 채우지 않음. 항목 순서는 쪽 기준 순서로 정렬.
- 서버는 생성 결과를 저장하지 않아 virtual 표시가 원래 생성 결과와 같은지 인증하지 못함(형식만 검사해 보존). 서명 토큰 등은 추가하지 않음.

출력·배치
- A4 세로(595.28×841.89pt) 정확히 4쪽, 선택·검색 가능한 텍스트, BytesIO → bytes. 출력 후 pypdf로 4쪽·A4 재확인(업로드용 inspect_pdf 상한은 용도가 달라 쓰지 않음).
- 배치는 화면 CSS px 값을 상수로 옮기고 PX = 595.2756/794 pt/px로 변환. 색·글자 크기·이미지 위치·object-position 크롭을 재현.
- 고정 문구는 서버 상수: 쪽 머리말·제목(4쪽 "Amostras e condições comerciais"), 항목명(pt-BR 상수, 번역 검수 전), 비공식 안내(모든 쪽 하단), AI 콘셉트 이미지 안내, 가상 안내(문구 "Inclui informações fictícias…", 항목 "Condições fictícias…"), 빈 상태 문구, 마무리 상담 문구. 표지 표시명이 virtual이면 표시명 아래에도 가상 안내.
- 넘침: 실제 글꼴로 높이·너비를 측정해 쪽별 영역(표지 문구는 이미지 띠 위까지, 본문은 하단 안내 위까지, 4쪽 마무리 이미지 최소 200px, 하단 안내 한 줄)을 넘으면 `BROCHURE_PDF_LAYOUT_OVERFLOW`(422, 쪽 번호·영역, 사용자 문구 미포함). 큰 글자 표시명·제목에 들어가지 않는 한 단어도 넘침. 본문은 긴 단어를 줄 안에서 나눔(화면 overflow-wrap과 같은 취지). 자르기·숨기기·글자 축소 없음.
  - 4쪽 공급 값: 24자 이하는 큰 숫자 위계, 단 한 단어가 칸을 넘으면 긴 값 글자 크기(18px)로 표시.
- 자산: 이미지 2개(크기 1024×1536·1448×1086 확인, 메모리에서 JPEG 품질 88로 포함, 각 1회만 포함)와 글꼴 2개(`features/product_brochure/fonts/`, 경로는 `FONT_DIR` 한곳)를 렌더링할 때 확인. 없음·손상·크기 다름 → `BROCHURE_PDF_ASSET_UNAVAILABLE`(500), 글꼴에 없는 문자 → `BROCHURE_PDF_GLYPH_MISSING`(422). 앱 시작에는 영향 없음.
- OpenAI·외부 네트워크·로그·디스크 쓰기 없음.

화면과 PDF의 알려진 차이(ReportLab ≠ 브라우저)
- 글꼴: 화면은 시스템 글꼴(Pretendard/맑은 고딕 등), PDF는 Noto Sans KR 정적 400/700. 굵기 500(medium)은 400으로, 가상 안내의 기울임(italic)은 글꼴이 없어 일반체로, 제목 자간 -0.02em은 미적용.
- 줄바꿈·글자 폭 차이로 줄 수가 다를 수 있음. 3쪽 상세 목록은 화면에 별도 스타일이 없어 PDF에서 항목명(작은 회색)+값+구분선으로 배치.
- 항목명: PDF는 서버 상수, 화면 미리보기는 AI 생성 라벨 → 다음 단계에서 화면도 같은 상수로 맞출지 [미정].
- 이미지는 JPEG 손실 압축(해상도 유지).

미검증: PDF의 쪽별 시각 확인(이미지 렌더링 도구 없음), 다른 PDF 뷰어·인쇄, 실제 생성 결과로 출력, 동시 요청 시 메모리·시간.
