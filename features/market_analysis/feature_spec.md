# 시장 분석
담당: 한윤수
상태: 사용자 협의 반영 최종 요구사항 명세(2026-10-25). 구현: 1단계(ComexStat 통계·계산·화면) 완료·실제 통계 대조 통과, 2단계(KOTRA·네이버·GDELT 수집, AI 분석·5차례 검토) 코드·모의 테스트 완료·실제 연결은 키 미설정으로 미검증, 3단계(PDF) 완료·실제 통계로 렌더링 확인. KITA는 공식 연계 경로 미확인으로 '연결 확인 중'. 새로고침 유지는 공통 합의 전 보류. 구현 결정과 실제 확인 결과는 맨 아래 '1단계 구현 현황'과 '2~3단계 구현 현황'을 봅니다. 최종 확인 담당자는 한윤수이며 별도 마감일 제약은 없습니다.

## 목적/범위
- 사용자: 효성티앤씨 해외영업·마케팅 담당자. 흩어진 브라질 시장 정보와 자료를 한 화면에서 확인하고 영업·마케팅 판단에 활용합니다.
- 대상 시장: 브라질 수입 시장으로 고정합니다. 브라질은 수입국이며, 공급국은 브라질에 원사를 공급하는 중국·한국 등입니다.
- 대상 제품: 리젠 T2T 원사의 시장 탐색을 위해 폴리에스터 DTY부터 분석합니다. 실제 수출 품목코드는 공급 제품 사양 확인 후 확정합니다.
- ComexStat/KOTRA/한국무역협회(KITA)/뉴스를 모두 활용합니다. 수입액·수입량·추세·공급국·평균 수입단가를 제공합니다. 계산은 코드, 뉴스·보고서 해석은 OpenAI가 수행합니다.
- 무역 통계는 ‘전체 폴리에스터 DTY 시장’으로 표시합니다. 일반 원사·재생 원사·T2T를 통계에서 구분하지 못하면 재생·T2T 관련 근거 자료를 별도로 제공합니다. 전체 DTY 수입액·수입량을 T2T 수요나 시장 규모로 단정하지 않습니다.
- 파일 업로드 없이 외부 자료를 자동으로 가져와 분석합니다. 엑셀·CSV 업로드와 내부 수출 실적 비교는 이번 범위에 포함하지 않습니다.
- 자료 수집은 공식 API를 최우선으로 사용합니다. 사용자의 API 키 활용 선호에 따라 인증키 기반 API를 적극 활용하되, ComexStat처럼 공개 조회에 키가 요구되지 않는 공식 API도 사용합니다. 기관별 API 제공 범위·권한을 확인하며, API가 확인되지 않은 자료를 자동 수집 가능한 것으로 간주하지 않습니다.

## 입력·출력·데이터: 채울 항목
- 품목코드: 기본 품목은 폴리에스터 DTY이며 사용자가 코드를 직접 입력해 변경할 수 있습니다. HS 6자리와 브라질 NCM 8자리를 구분해 안내합니다. 코드 형식·유효성·해당 기간의 적용 여부를 실제 분류 자료로 검증합니다.
- 시장 분석용 초기 후보: HS 5402.33 및 NCM 5402.33.10(미염색), 5402.33.20(염색), 5402.33.90(기타). 이는 대화에서 조사한 분석 후보이며 실제 수출 신고 코드 확정이 아닙니다. 기본 DTY 조회에 포함할 NCM 묶음은 현행 분류와 데이터 접근 검증 후 확정하고 화면에 표시합니다. 여러 품목 동시 비교는 미정입니다.
- 기간: 월 단위로 선택합니다. 기본값은 통계가 제공되는 최신 월을 포함한 최근 36개월이며 최대 조회 기간은 120개월입니다. 최신 월과 미완결 기간 여부를 안내합니다.
- 공급국: 기본값은 전체 국가입니다. 여러 공급국을 선택해 비교할 수 있습니다. 대상 시장 브라질과 공급국 필터를 구분해 표시합니다.
- 입력 파일 형식·용량: 업로드 기능이 없으므로 해당 없음입니다.
- 표시 단위: 수입액 USD, 수입량 톤(t), 평균 수입단가 USD/kg. 계산은 원본 순중량 kg을 사용하고 화면의 톤 표시는 kg ÷ 1,000으로 변환합니다.
- 평균 수입단가: 동일 품목·기간·공급국 조건의 FOB 수입액 합계(USD) ÷ 순중량 합계(kg). 국가별·월별 단가를 단순 평균하지 않습니다. 명칭은 ‘평균 수입단가(FOB, USD/kg)’이며 리젠 T2T 견적·실제 판매가격·운임과 세금을 포함한 도착가격으로 해석하지 않습니다.
- 결측·이상치: 중량이 없거나 0이면 ‘계산 불가’로 표시합니다. 결측값을 임의로 0으로 채우지 않으며, 일부 자료 누락 시 영향받는 집계 범위와 불완전 여부를 밝힙니다. 유난히 높거나 낮은 단가는 삭제하지 않고 ‘확인 필요’로 표시합니다. 이상치 판정 기준·반올림 자리수·검증 허용 오차는 구현 전 확정합니다.
- 추세: 월별 수입액·수입량·평균단가와 전년 동기 대비를 제공합니다. 증감률은 (현재 값 − 전년 동기 값) ÷ 전년 동기 값 × 100이며 비교 기간·품목 범위를 맞춥니다. 전년 값이 0이거나 없으면 계산 불가 사유를 표시합니다. 화면 조회 기간 밖의 전년 비교 자료가 필요하면 별도로 확보합니다.
- 공급국: 수입액 기준 상위 10개국, 국가별 비중, 한국의 순위·비중을 제공합니다. 한국은 상위 10개국에 없어도 별도로 표시합니다. 기본 비중은 동일 품목·기간의 브라질 전체 수입액을 분모로 하며, 공급국 비교 필터에서도 전체 시장 기준임을 명시합니다.
- 출처: 통계·분석 문장에 출처명, 원문 링크, 자료 기준일 또는 발행일을 연결하고 마지막 확인 시각을 표시합니다. 서로 다른 수치는 기간·품목·단위를 우선 비교하며 브라질 수입 통계의 기준 출처는 ComexStat으로 둡니다. 차이가 해소되지 않으면 함께 표시합니다.
- 실제 테스트 자료: 사용자가 제공한 기존 보고서·통계 자료는 없습니다. 구현 시 공식 자료에서 동일 조건의 대조 사례를 선정하고 실제 조회 조건·출처·관측값을 기록합니다. 현재 검증용 수치나 성공 사례는 확보된 것으로 간주하지 않습니다.

## 공통 조건
- 로그인·사용자 결과 장기 저장·작업 이력·탭 간 자동 연동 없음. 다른 기능 탭으로 조건·결과를 자동 전달하지 않습니다.
- 탭 이동 및 새로고침 시 입력값·분석 결과를 유지하고 브라우저 종료 후에는 초기화합니다. 공개 시장 데이터 캐시는 사용자 작업 상태와 별도로 관리합니다.
  - 현재 상태(2026-10-25): 탭 이동 유지는 구현됨. 새로고침 유지는 공통 담당 합의 전까지 보류(아래 '새로고침 유지 구현안' 참고). 지금은 새로고침하면 결과가 사라지고 공통 종료 경고가 표시됩니다.
- 이번 새로고침 유지 요구는 README 및 docs/decisions.md, docs/design_system.md의 기존 ‘새로고침 후 복원 없음’보다 최신 사용자 결정입니다. 구현 시 공통 담당자와 상태 관리·종료 경고 동작을 조정하고 관련 공통 문서를 갱신해야 합니다. 현재 명세 작성으로 공통 코드가 변경된 것은 아닙니다.
- 새로고침과 종료를 구분하는 저장 방식, 브라우저의 종료 후 세션 복원·강제 종료에서의 초기화 보장 범위는 구현 전 검증합니다. sessionStorage 등 특정 수단만으로 모든 종료 상황이 보장된다고 가정하지 않습니다. 지원 브라우저와 예외는 검증 결과에 따라 명시합니다.
- 결과물은 A4 세로형 PDF로 다운로드합니다. 조회 조건, 핵심 수치, 그래프·표, AI 분석, 출처 링크·자료 기준일을 포함합니다.
- 화면은 docs/design_system.md의 공통 UI·디자인 토큰·접근성 기준을 따릅니다. AI 해석은 한국어 표로 일목요연하게 제공합니다.
- 출처 없는 수치·인증·공급 조건을 AI로 채우지 않습니다. 사실·추정·미확인을 구분하며 모델의 출력이나 반복 검토 자체를 사실의 근거로 사용하지 않습니다.
- 근거가 부족하면 검색어·언어·출처·조회 기간을 넓혀 공식 원문까지 추가 조사합니다. 기본 수집 기간 밖의 자료는 날짜와 사용 이유를 표시합니다. 끝내 확인할 수 없는 정보는 ‘근거 부족/미확인’, 출처가 충돌하면 ‘출처 간 차이’로 표시하고 조사 범위와 남은 불확실성을 설명합니다. 존재하지 않거나 공개되지 않은 정보를 반드시 확보한다고 보장하지 않습니다.
- API 키·고객 기밀·사용자 결과를 코드나 로그에 남기지 않습니다. OpenAI 호출은 서버의 공통 연결을 활용하며 키를 화면이나 PDF에 노출하지 않습니다.
- 데이터 제공기관의 인증키와 OpenAI 인증키는 별도로 관리합니다. 키는 서버 환경변수 등 비밀 설정에 보관하고, 브라우저·저장소·요청 URL 로그에 노출하지 않습니다. 환경변수 이름은 구현 시 공통 규칙에 맞춰 확정하고 비밀값 없는 설정 예시에만 추가합니다.
- 자료의 API 접근 권한과 재사용 권한은 별도로 확인합니다. 특히 KOTRA 뉴스의 업무용 AI 요약·번역·PDF 재배포 및 캐시는 해당 이용 조건에서 허용되는 범위로 제한합니다. 이용 범위가 불명확하면 제공기관 확인 전 해당 처리를 활성화하지 않고 연결 상태와 제한 사유를 표시합니다.

## 구현 전 작성
- 입력 필드/형식:
  - 대상 시장: 필수, 브라질 고정 표시.
  - 품목: 필수, 폴리에스터 DTY 기본값 및 품목코드 직접 입력. 코드 체계와 명칭을 함께 표시하며 지원 코드 범위·매핑은 실제 데이터 연결 시 확정합니다.
  - 시작 월·종료 월: 필수, YYYY-MM. 최신 제공 월까지 최근 36개월 기본값, 최대 120개월.
  - 공급국: 선택, 전체 국가 기본값, 복수 선택 지원.
  - 잘못된 코드·빈 필수값·기간 역전·기간 초과는 해당 입력란 아래 이유와 수정 방법을 안내합니다. 예: ‘시작 월이 종료 월보다 늦습니다. 기간을 다시 선택해 주세요.’
  - 뉴스·보고서 수집은 기본적으로 최근 6개월을 사용하며 통계 조회 기간과 구분해 표시합니다.
- 결과 형식/견본:
  - 화면 순서: ① 핵심 수치(수입액·수입량·평균단가·전년 동기 대비) → ② 시장 추세(월별 그래프·상세 표) → ③ 공급국 비교(상위 10개국·한국 현황) → ④ AI 분석 표 → ⑤ 근거 자료(뉴스·보고서 링크·자료 기준일).
  - AI 분석은 핵심 요약 3~5줄, 변화의 배경, 영업 기회 최대 3개, 위험 최대 3개로 구성합니다. 근거가 부족한데 정해진 개수를 채우기 위해 내용을 생성하지 않습니다.
  - AI 표의 기본 열: ‘구분 | 핵심 내용 | 영업·마케팅 시사점 | 사실/추정/미확인 | 출처·기준일’. 이는 배치용 양식이며 실제 수치·사례는 검증된 자료로 채웁니다.
  - 뉴스와 수입 추세의 동시 발생만으로 인과관계를 단정하지 않습니다. 리젠 T2T 관련 시사점은 전체 DTY 통계와 제품별 근거를 구분해 설명합니다.
  - PDF는 화면의 주요 내용과 조회 조건을 재현하며 한글·포르투갈어, 페이지 나눔, 긴 표·URL, 그래프 잘림을 확인합니다. PDF 라이브러리와 세부 디자인은 기존 프로젝트 기준을 확인해 선정합니다. → ReportLab 5.1.0 + Noto Sans KR로 구현(2단계 현황 참고).
- 엔드포인트/요청/응답:
  - 구현 위치: C:\Users\user\Desktop\fionex\features\market_analysis. 기존 Flask + HTML/CSS/JavaScript 구조와 기능 Blueprint를 따릅니다.
  - 분석 조회·재조회·PDF 생성에 필요한 내부 엔드포인트, 메서드, 실제 JSON 필드명은 아래 '1단계·2~3단계 구현 현황'의 엔드포인트 절에 확정했습니다.
  - 요청에 필요한 의미상 항목: 품목코드와 체계, 시작·종료 월, 선택 공급국, 재조회 여부. 브라질 수입 시장 조건은 서버에서도 고정·검증합니다.
  - 응답에 필요한 의미상 항목: 적용 조회 조건, 핵심 지표, 월별 추세, 공급국 순위·비중·한국 현황, AI 분석 표, 근거 링크, 기준일·확인 시각, 출처별 성공/실패, 결측·계산 불가·이상치·캐시 상태, 5차례 검토 상태.
  - OpenAI API는 사용자가 보유한다고 확인했습니다. 실제 실행 환경의 키 설정·선택 모델·시장 분석 기능 호출은 별도 검증 대상입니다. 기존 common/ai_client.py 및 docs/data_contracts.md를 확인해 연결합니다.

### ComexStat 실제 호출로 확인한 동작 (2026-10-25)
- POST /general의 period는 "연도 범위 × 월 범위"로 해석된다. 2024-01~2026-09 요청 시 매년 1~9월만, 2022-10~2026-09 요청 시 빈 목록. → 항상 YYYY-01~YYYY-12 전체 연도로 요청하고 서버에서 월을 잘라낸다. 2022-01~2026-12 요청은 2022-01~2026-09 57개월을 빠짐없이 반환했다.
- HS 6자리 필터 이름은 subHeading(구 이름 sh6는 거부된다는 comexr 변경 기록 확인). 국가 필터는 3자리 코드(한국 190, 중국 160). 응답의 국가는 포르투갈어 이름만 온다.
- 금액(metricFOB)·순중량(metricKG)은 문자열. 코드 검증은 GET /tables/ncm?search=, /tables/hs?search=(없는 코드는 빈 목록).
- 약 30초 간격 연속 호출에서 HTTP 429. 공식 한도 수치는 찾지 못했다. 서버는 호출을 하나씩 보내고 최소 10초 간격, 429·5xx·연결 실패만 15초·30초 후 최대 2회 재시도한다. 첫 조회는 수십 초 걸릴 수 있다.

### 엔드포인트 (2~3단계 추가)
- POST /api/market-analysis/analyze 응답에 bundle_id 추가. 조회 묶음(공개 통계·공개 기사·AI 진행 상태)은 서버 메모리에 3시간·최대 30개 보관, 서버 재시작 시 사라짐(디스크·DB 없음).
- POST /api/market-analysis/news {bundle_id, refresh} → window{from,to,months,note}, items[{id, source, source_name, title, url, published, collected_at, language, excerpt, access, usage_note, ai_input, pdf_text, copyright_policy, topics, score}], candidates, sources[{source, label, state(ok|config|auth|rate_limited|unavailable|bad_response|rejected|pending), status_text, count, message, usage_note}]. 410 MA_BUNDLE_EXPIRED.
- POST /api/market-analysis/ai {bundle_id} → complete, has_draft, rows[{section, content, implication, status, model_status, source_ids, sources[{id,name,url,date}], flags}], gaps, remaining_findings, rounds[{number, title, checked, changes, evidence, unresolved, model_completed, code_findings_before, code_findings_after, rows_changed, status}], rounds_total, usage, prompt_versions, status, error, reused. 409 MA_NEWS_REQUIRED·MA_AI_RUNNING, 410.
- POST /api/market-analysis/pdf {stats, news, ai} → application/pdf 첨부(market_analysis_<코드>_<시작>_<종료>_<생성일>.pdf). 요청 3 MiB 상한(413), 형식 오류 400, 생성 실패 500.

### 새로고침 유지 구현안 (공통 합의 전 보류, 코드 변경 없음)
- 최초 요구: 새로고침 시 유지, 브라우저 종료 시 초기화. 현재 공통 규칙: 사용자 자료를 브라우저 저장소에 쓰지 않음, 새로고침 시 복원 없음(docs/development.md, docs/design_system.md).
- 변경 범위(공통): static/js/app_shell.js·leave_guard.js에 탭별 상태 저장·복원 API 추가, docs/development.md·design_system.md·decisions.md·README의 저장 정책 수정, 종료 경고 문구 조정.
- 구현안: sessionStorage에 탭별 입력값과 결과 JSON(통계·기사·AI)을 저장하고 로드 시 복원. 비밀값·키는 넣지 않음. 결과에 bundle_id가 있어도 서버 묶음이 만료됐을 수 있으므로 복원 후 AI 이어하기는 410을 안내.
- 한계: sessionStorage는 탭 단위이며 브라우저의 '세션 복원'·'탭 다시 열기'로 되살아날 수 있고, 강제 종료 후 복원 동작은 브라우저마다 다름. 모든 종료 상황의 초기화를 보장하지 않음. 저장 용량 한도(일반적으로 수 MB)도 있음. 지원 브라우저별 실제 확인이 필요.
- 대안: 복원 없이 '결과를 PDF로 받아 두기'를 유지(현재 방식).

### 자료 갱신 방식 선택지 (배포 환경 미정)
- 현재: 요청 시점 확인. 요청이 들어올 때 KST 날짜가 바뀌었으면 다시 받음(ComexStat·네이버·GDELT). 서버가 꺼져 있거나 요청이 없으면 갱신도 없음. '하루 한 번 자동 수집'이 아님.
- 선택지 ① 현재 방식 유지(단순, 첫 조회가 느릴 수 있음). ② 서버 안 예약 작업(APScheduler 등, 프로세스가 하나일 때만 안전, 패키지 추가 필요). ③ 배포 플랫폼의 예약 작업(cron)이 갱신 엔드포인트 호출(배포 환경 결정 후). ④ 외부 저장소 캐시(파일·Redis 등, 여러 프로세스 공유).
- 어느 방식이든 자료 갱신과 유료 AI 재실행은 분리. AI는 사용자가 버튼을 눌렀을 때만 실행하며 자동 재실행 없음.

### 남은 일 (사용자·외부 결정 필요)
- KOTRA: 공공데이터포털 활용 신청·서비스키 설정 후 실제 기사 수신·필드 확인. 업무용 AI 요약·번역·PDF 수록·캐시 허용 여부를 KOTRA(AI플랫폼팀)에 확인해 USAGE 표 갱신.
- 네이버: 애플리케이션 등록·키 설정 후 실제 수신 확인. 검색 요약의 AI 입력·PDF 수록이 이용약관상 허용되는지 확인(현재 허용으로 설정, 확인 필요 표시).
- GDELT: 다른 시간대·네트워크에서 실제 응답 필드 확인. 계속 429면 연결 해제 여부 결정.
- KITA: 제휴·데이터 제공 문의 여부 결정.
- OpenAI: 키 설정 후 승인 범위(최대 3회) 안에서 실제 품질·토큰·비용·소요 시간 확인, 모델 최종 선정·비용 한도.
