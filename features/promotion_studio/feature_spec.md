# 홍보 스튜디오 상세 기능 명세

- 서비스: fionex
- 담당: 정은진 단독 담당
- 기능 경로: `features/promotion_studio/`
- 개인 기록: `docs/worklogs/jeong_eunjin/`
- 정리일: 2026-10-25 (Asia/Seoul)
- 상태: 사용자 요구사항 구체화 완료 / 기술 설계 일부 미정 / 2단계(입력 폼·검증) 구현·검증 완료 / 4단계 중 텍스트 콘티 생성·표시 구현(모의 검증 + 실제 호출 1회, 프롬프트 개선 필요) / 3단계·편집·이미지·PDF 미구현
- 근거: 첨부된 기존 명세, 앞서 조회한 develop 문서, 이후 단계별 사용자 답변. 이 파일은 저장소에 반영되지 않은 상세 초안이다. 개발 전 최신 develop 및 로컬 변경을 다시 확인한다.

## 1. 목적과 범위

효성티앤씨 해외영업·마케팅 담당자가 브라질 시장의 리젠 T2T 홍보를 위해 바이어용 또는 소비자용 영상 콘티를 제작한다. 포르투갈어와 한국어 검토본, 업로드 사진 활용, AI 장면 이미지 생성, 편집 및 다운로드를 지원한다. 실제 영상·음성 생성은 범위에 포함하지 않는다. 내레이션은 텍스트다.

### 기존 문서와 달라진 결정

| 항목 | 기존 | 이번 사용자 확정 |
|---|---|---|
| 담당 | 한윤수·정은진 공동 | 정은진 단독 |
| 결과물 | PDF | PDF + PNG/JPG 개별 이미지 + ZIP |
| 장면 이미지 | 미정 | 업로드 사진 활용 및 OpenAI 자동 생성 |
| 검토 언어 | 미정 | 포르투갈어 + 한국어 |

공통 문서의 담당·PDF 전용 규칙은 팀과 조율해 반영한다. 이 명세가 팀 공통 파일을 임의로 수정할 권한을 뜻하지 않는다.

## 2. 사용자 흐름

1. 대상, 제품 설명, 홍보 목적, 톤, 영상 길이, 장면 수, 화면 비율, 이미지 스타일을 입력한다. 문서·사진·로고·CTA는 선택적으로 제공한다.
2. 문서와 OCR 추출 내용을 확인·수정한다. 자료 충돌은 사용자가 선택·수정한다. 근거 부족 주장은 보완하거나 삭제한다.
3. 텍스트 콘티와 한국어 검토본을 생성한다. 제목은 AI가 제안하고 사용자가 수정한다.
4. 직접 편집 또는 AI 수정 요청으로 콘티를 검토한다. AI 수정은 전후 비교 후 적용·취소한다.
5. 전체 또는 선택 장면의 이미지 생성 장수·예상 비용을 확인한 뒤 실행한다.
6. 사진 연결, 이미지 재생성 비교, 자막·로고 배치를 조정한다.
7. PDF, 장면별 이미지, 전체 이미지 ZIP을 다운로드한다.

## 3. 입력 명세

| 입력 | 확정 요구사항 |
|---|---|
| 대상 | 바이어용·소비자용 중 선택 |
| 제품 설명 | 직접 입력 필수, 최대 3,000자 |
| 보조 문서 | 선택, PDF·DOCX·PPTX·HWP·XLSX·TXT, 최대 3개 |
| 문서 용량 | 파일당 20MB, 합계 60MB |
| 영상 길이 | 15초·30초·60초·90초 |
| 장면 수 | 길이에 관계없이 3~15개 중 사용자 선택 |
| 홍보 목적 | 최대 2개 선택, 기타 직접 입력 포함 |
| CTA | 직접 입력만 제공, 선택 사항. 비워두면 임의 생성하지 않음 |
| 홍보 톤 | 전문적·신뢰감 / 감성적 / 활기찬 / 고급스러운 / 기타 직접 입력 |
| 제품 사진 | 선택, 최대 5장 |
| 로고 | 선택, 최대 1개 |
| 사진·로고 형식 | JPG·JPEG·PNG·WEBP |
| 사진·로고 용량 | 파일당 10MB, 합계 60MB. 문서 용량 제한과 별도 |
| 화면 비율 | 16:9·9:16·1:1·4:5 중 콘티 한 편에 하나 선택, 전 장면 동일 |
| 이미지 스타일 | 실사형·일러스트형·스케치형·3D 렌더형·기타 직접 입력 |
| 최대 대기 시간 | 기본값 제공 + 허용 범위 안에서 초 단위 직접 입력. 기본값·상한·하한 미정 |

홍보 목적 선택지: 제품 소개 / 브랜드 인지도 향상 / 친환경 가치 전달 / 바이어 상담·문의 유도 / 소비자 구매 유도 / 협업·파트너십 제안 / 기타 직접 입력.

### 기본값·글자 수 제한 (2026-10-25 사용자 확정)

| 항목 | 값 |
|---|---|
| 대상·홍보 톤·홍보 목적 | 기본 선택 없음, 사용자가 반드시 선택 (목적 1~2개) |
| 영상 길이 / 장면 수 / 화면 비율 / 이미지 스타일 | 30초 / 6개 / 16:9 / 실사형 |
| CTA | 최대 200자 |
| '기타' 직접 입력(목적·톤·스타일) | 각 최대 50자, 기타 선택 시 필수 |
| AI 수정 요청 | 최대 1,000자 (5단계에서 사용) |
| 최대 대기 시간 | 기본 180초, 30~600초 정수 |
| 로고 적용 범위 | 로고를 올리면 입력 폼에서 선택. 기본값 없음(필수 선택) |

제한값의 단일 원본은 `service.py`의 `LIMITS`·`DEFAULTS`다. 화면(panel.html)은 routes.py의 context processor로 같은 값을 받는다.
입력 검증은 브라우저(promotion_studio.js)와 서버 함수(`service.validate_input`)에 같은 규칙으로 구현했다. 서버 함수는 콘티 생성 API가 생기면 요청 처리 전에 호출한다. 이미지 파일은 확장자 외에 파일 앞부분 서명(JPG·PNG·WEBP)을 확인한다. 문서 내용 검사는 3단계(문서 추출)에서 한다.
Flask 요청 전체 크기 상한(`MAX_CONTENT_LENGTH`)은 app.py 공통 설정이라 아직 지정하지 않았다. 생성 API 추가 전에 공통 담당과 조율한다.

## 4. 문서 분석·OCR·근거 검토

- 스캔 PDF와 문서 속 이미지의 글자를 OCR로 추출한다. 추출 결과는 사용자가 확인·수정할 수 있다.
- 업로드 전체 합계: 문서·슬라이드 최대 100쪽, OCR 처리 최대 40쪽, 엑셀 비어 있지 않은 셀 10,000개, 추출 텍스트 10만 자.
- 각 제한은 별도로 적용한다. OCR은 문서 처리량 중 OCR 대상에 대한 추가 제한이다. 세부 쪽수 산정 방식은 기술 설계에서 정한다.
- 제한 초과 시 임의로 잘라 사용하지 않고 자료 축소 또는 처리 범위 선택을 안내한다.
- 직접 입력과 자료 사이에 발견된 충돌은 표시한다. 사용자가 사용할 내용을 선택·수정한 뒤 생성한다. 모든 충돌을 자동 탐지한다고 보장하지 않는다.
- 수치·인증·친환경 주장·공급 조건 등 근거 부족 항목은 자료 보완 또는 주장 삭제 후 생성한다. AI 출력 자체를 사실의 근거로 삼지 않는다.
- 리젠 T2T와 다른 제품의 정보를 혼동하지 않는다. 확인된 자료 범위 밖의 제품 사실을 채우지 않는다.
- 장면별 근거 연결 정보는 관리하되, 사용자에게 보여주는 출처·확인 필요 사항은 마지막 별도 페이지에 모아 장면 번호와 연결한다.
- 사진·로고가 없어도 생성 가능하다. 참고 사진이 없으면 실제 제품 외형의 재현 여부를 확인할 수 없다는 점을 검토 대상으로 남긴다.
- 자료 출처·갱신 정책, 테스트 자료, 형식별 파서·OCR 도구는 미정이다. HWP 및 복잡한 문서 변환, 암호화·손상 파일, 이미지 기반 문서의 지원 수준을 실제 검증한다.

## 5. 콘티 결과와 편집

### 장면별 항목

- 장면 번호
- 시작·종료 시간과 장면 길이
- 화면 설명: 배경·제품·인물·동작, 포르투갈어 + 한국어
- 카메라 구도·움직임: 포르투갈어 + 한국어
- 자막: 포르투갈어 + 한국어 검토본
- 내레이션: 포르투갈어 + 한국어 검토본
- 이미지 영역: 업로드 사진 또는 생성 이미지

### 편집 규칙

- 직접 편집과 AI 수정 요청을 모두 지원한다.
- AI 수정 범위는 전체 또는 선택 장면이다. 수정 전후 비교 후 적용·취소한다.
- 선택 장면 AI 수정은 기존 장면 시간을 유지하며 다른 장면을 임의 변경하지 않는다.
- 장면별 시간 직접 수정 가능. 합계가 선택한 영상 길이와 다르면 안내하고 이미지 생성·PDF 다운로드를 제한한다.
- 순서 변경 시 장면 번호와 시작·종료 시간을 갱신한다. 장면의 내용·이미지·길이는 함께 유지한다.
- 생성 후 장면 추가·삭제를 허용하되 총 3~15개를 유지한다. 변경 후 전체 시간을 맞춘다.
- 새 장면은 빈 장면 직접 작성 또는 AI 작성 요청으로 추가한다.
- 한쪽 언어를 수정하면 다른 언어의 번역 확인 필요 상태를 표시한다. 번역 갱신 버튼으로 번역안을 검토하고 적용한다.
- 미확인 번역이 있어도 안내 후 사용자가 선택하면 PDF 다운로드를 허용한다.
- 콘티 수정 후 기존 이미지는 유지하되 재생성 필요 안내를 표시한다. 자동 재생성하지 않는다.
- 대상·길이·장면 수 등 입력 조건을 변경해도 기존 결과는 유지한다. 변경 조건과 기존 결과의 불일치를 표시하고 재생성을 안내한다. 기존 결과의 시간을 새 조건에 맞춰 자동 변경하지 않는다.

## 6. 이미지 생성과 편집

### 생성

- 텍스트 콘티 확인 후 별도 버튼으로 이미지를 생성한다.
- 전체 장면 또는 선택 장면 생성을 지원한다.
- 서비스 주 모델은 `gpt-6.1-sol`로 선정했다. 콘티·번역·수정 및 이미지 생성 도구 호출을 담당한다.
- 실제 이미지 생성은 OpenAI 이미지 생성 도구의 GPT Image 모델을 사용한다. 세부 이미지 모델·SDK·설정은 미정이다. 모델 이용 권한·지원 비율·호출 방식은 구현 직전 공식 문서와 실제 계정으로 확인한다.
- 힉스필드는 사용하지 않는다. AI 호출은 서버에서 공통 클라이언트를 통해 처리하며 키를 브라우저에 노출하지 않는다.
- 제품 사진은 AI가 장면에 자동 연결하고, 사용자가 변경·해제할 수 있다. 연결 사진을 해당 장면의 제품 외형 참고 자료로 사용한다.
- 제품 색·형태 유지가 우선이며 배경·연출을 변경한다. 완전한 일치는 보장하지 않으며 사람이 검토한다.
- 재생성 수정 요청은 선택 입력이다. 비우면 기존 조건으로 재생성한다.
- 재생성 중·실패 시 기존 이미지를 유지한다. 성공하면 기존·새 이미지 비교 후 사용자가 선택한다.

### 자막

- 장면별로 포르투갈어 자막 합성을 켜고 끈다. 원문은 콘티에서 편집 가능하다.
- 이미지 생성 후 별도 합성한다. 드래그로 자유롭게 위치를 배치한다.
- 글자 크기·색상·글꼴·굵기·정렬·외곽선·배경 박스 켜기/끄기·배경 투명도를 편집한다.
- 사용할 글꼴 목록은 사용권과 포르투갈어 문자 지원 확인 후 확정한다.

### 로고

- 적용 범위: 장면 이미지 + 콘티·PDF / 콘티·PDF만 중 선택.
- 장면 이미지에는 생성 후 원본 로고를 합성한다.
- 장면별 드래그 이동 및 원본 비율 유지 크기 조절을 제공한다.
- 자막·로고 배치는 PDF와 이미지 다운로드에 반영한다.

## 7. 다운로드

### PDF

- 다운로드 시 포르투갈어·한국어 병기본 또는 포르투갈어 전용본을 선택한다.
- 표지 포함: 콘티 제목·대상·홍보 목적·영상 길이·업로드한 로고. 화면 비율은 표지에 표시하지 않는다.
- 한 페이지에 1장면을 배치한다.
- 근거 출처·확인 필요 사항은 장면 페이지에서 분리하고 문서 마지막에 별도 페이지로 배치한다.
- 이미지가 없거나 일부 생성에 실패해도 텍스트 중심으로 PDF 다운로드를 허용한다.
- 번역 미확인은 안내 후 다운로드 가능하다. 시간 합계 오류는 수정해야 한다.
- 용지 크기·방향·최종 레이아웃·글꼴·긴 내용 넘침 처리는 PDF 구현 전 정한다. 마지막 근거가 한 페이지에 들어가지 않는 경우의 처리도 검증한다.

### 이미지·ZIP

- 자막·로고가 반영된 최종 장면 이미지를 개별 다운로드한다.
- PNG·JPG 중 사용자가 선택한다.
- 전체 이미지 ZIP 다운로드를 제공한다. 준비된 이미지만 포함하며 제외되는 장면 번호를 사전 안내한다.
- 파일명 규칙, 이미지 해상도·JPG 품질·PNG 투명 배경 처리는 미정이다.

## 8. 오류·비용·취소

- 이미지 생성·재생성 실행 전 대상 장수와 예상 비용을 안내하고 사용자 확인 후 실행한다. 예상 비용과 실제 청구액은 다를 수 있다.
- 별도의 콘티당 비용 상한은 확정하지 않았다. 비용 산정 기준·통화·가격 갱신 방식·이미지 외 요청 비용 안내는 기술 설계에서 정한다.
- 일부 이미지 실패 시 성공 결과를 보존하고 실패 이유와 장면 번호를 안내한다. 자동 재시도 없이 사용자가 실패 장면을 재시도한다.
- 처리 중 취소 버튼을 제공한다. 취소 시 입력과 완료된 결과를 보존한다.
- 제한 시간 초과는 안내 후 사용자 재시도 방식이다. 사용자가 초 단위 최대 대기 시간을 입력할 수 있지만 서버 허용 범위 내에서만 적용한다.
- 취소·시간 초과 후에도 이미 전송된 요청은 완료되거나 과금될 수 있음을 안내한다.
- 중복 실행을 막고 오류 후 입력을 보존한다. 실패·취소 이후 늦게 도착한 응답의 반영 규칙은 구현 전 정한다.
- 문서 읽기 실패·손상·암호화·형식 불일치·용량 초과, OCR 실패, 모델 응답 형식 오류, API 제한·인증 오류, PDF·이미지 출력 실패를 구분해 안내하도록 설계한다. 내부 경로·키는 노출하지 않는다.

## 9. 공통 구조·보관·협업

- 로그인, 사용자 결과물의 장기 저장·이력·재접속 복원, 탭 간 자동 데이터 연결은 없다.
- 같은 페이지의 탭 이동 시 입력·파일·결과를 메모리에 유지한다. 탭 복귀로 API를 다시 호출하지 않는다.
- 새로고침·페이지 이탈 시 복원하지 않는다. 보호할 작업이 있으면 공통 이탈 경고를 사용한다. 브라우저에 따라 경고가 제한될 수 있다.
- localStorage·sessionStorage·IndexedDB·서버 DB·디스크 로그에 사용자 자료와 결과를 영구 저장하지 않는다. 임시 파일이 필요하면 성공·실패 모두 정리한다.
- 편집 비교를 위한 현재·대안 결과는 현 페이지 메모리에 한정하며 영구 이력이 아니다.
- 기존 공통 디자인·CSS 토큰·접근성·AppShell 작업 상태 API를 사용한다. 다운로드 요청을 실제 저장 성공으로 표시하지 않는다.
- 부분 이미지 다운로드가 전체 미다운로드 결과 경고를 해제하지 않도록 공통 상태 API와의 연계 방식을 조율한다. 기존 API만으로 지원된다고 가정하지 않는다.
- Conda jasonenv, Python 3.11, Flask, HTML·CSS·JavaScript를 따른다. 새 프레임워크를 임의 추가하지 않는다.
- 담당 기능과 개인 기록 밖의 변경은 대상·이유를 먼저 공유하고 수정 담당을 합의한다.
- Git 변경은 사람이 수행한다. Claude Code는 현재 브랜치·상태·diff만 읽기 전용으로 확인한다. main/develop에서 직접 개발하지 않는다.

## 10. API·데이터 계약: 구현 전 확정

기존 초안의 접두어 `/api/promotion-studio`를 기준으로 최신 `docs/data_contracts.md`를 확인한다.

### 구현: 텍스트 콘티 생성 (2026-10-25)

`POST /api/promotion-studio/storyboard` — multipart/form-data, 필드는 입력 폼과 같다(3장).

- 처리: `service.validate_input` → 오류가 있으면 AI를 호출하지 않고 400 → `service.generate_storyboard` → 공통 `generate_structured`(OPENAI_MODEL, 공통 timeout 60초·재시도 0).
- 프롬프트: `prompts/storyboard_generate_v1.md`. 모델 입력은 대상·제품 설명·목적·톤·스타일·CTA·길이·장면 수·비율 JSON이며 파일명·파일 내용은 보내지 않는다.
- 출력 상한: max_output_tokens = 2000 + 700 × 장면 수(추론 포함, 금액 한도 아님).
- 성공 200: `{"ok": true, "data": {title_pt, title_ko, scenes[{number, start_seconds, end_seconds, duration_seconds, visual_pt/ko, camera_pt/ko, subtitle_pt/ko, narration_pt/ko}], review_notes[], notices[], timing{total_seconds, expected_seconds, ok}, conditions{audience, duration, scene_count, aspect_ratio}, model, prompt_version}}`
- 시작·종료 시간은 모델이 낸 장면 길이로 코드가 계산하고 번호는 순서대로 다시 매긴다. 장면 수가 다르거나 길이가 1초 미만이면 결과를 버리고 `AI_OUTPUT_INVALID`(502)를 돌려준다. 합계가 영상 길이와 다르면 결과는 보여 주되 `timing.ok=false`로 경고하며 자동 보정하지 않는다.
- 실패: 입력 오류 400 `{"code": "INVALID_INPUT", "message", "fields": [{field, message}]}`, AI 오류는 `AIError.to_dict()`와 `http_status`(설정 누락 503, 시간 초과 504 등).
- 화면: 생성 중 버튼 비활성·취소 버튼·`aria-busy`. 브라우저는 최대 대기 시간이 지나면 기다리기를 멈춘다(서버 요청은 계속되어 과금될 수 있음을 안내). 실패·취소 시 입력과 기존 결과를 유지한다. 결과 뒤 입력을 바꾸면 "입력 조건이 바뀌었습니다"를 표시한다.
- 아직 반영하지 않음: 보조 문서·사진·로고 내용(업로드하면 안내 문구 표시), 제목 직접 수정·장면 편집, 이미지, PDF.
- 한계: 서버 쪽 대기 시간은 공통 TEXT_TIMEOUT_SECONDS(60초)라 사용자가 입력한 최대 대기 시간(30~600초)을 서버 요청에 적용하지 못한다. 장면이 많을 때 60초를 넘길 수 있다. 서비스 주 모델 `gpt-6.1-sol` 지정도 공통 ai_client 확장이 필요하다. 두 가지 모두 공통 담당과 조율할 대상이다.

필요 작업 단위: 문서 분석/OCR, 콘티 생성, 전체·선택 수정, 번역 갱신, 장면 추가, 사진 연결, 이미지 생성·재생성, PDF·이미지·ZIP 출력. 작업별 요청 필드·타입·상한·응답·오류·취소·시간 제한을 구현 전에 정의한다.

설계 권장안(사용자 확정 기술 스키마 아님): 재정렬해도 변하지 않는 장면 식별자, 편집 버전과 생성 기준 버전, 원본 이미지와 합성 설정의 분리, 출처의 파일/쪽/시트/셀 연결, 장면별 성공·실패 상태를 둔다. 현재 번호만으로 자료를 연결하지 않는다.

## 13. 권장 개발 순서와 남은 결정

1. 최신 규칙·기능 브랜치·변경 파일을 읽기 전용 확인. 단독 담당 및 이미지/ZIP 출력 변경을 팀 공통 문서와 조율.
2. 입력 폼·검증·탭 상태 연결.
3. 문서 추출·OCR·검토·근거 확인.
4. 텍스트 콘티 생성·직접 편집·시간·장면 관리.
5. AI 수정 비교·번역 갱신.
6. 사진 연결·비용 안내·이미지 생성·재시도·취소.
7. 자막·로고 편집·이미지 출력.
8. PDF·ZIP·공통 통합 검증.

각 단계는 더 작은 검증 단위로 나눈다. 이 순서는 권장안이며 개발 실행 지시가 아니다.

구현 전 남은 기술 결정: 이미지 모델·SDK·OCR/문서 파서·HWP 처리·PDF 도구·글꼴·출력 해상도/비율 처리·요청 계약·실행 제한·비용 산정·입력 기본값·자료별 처리량 산정·취소/늦은 응답·테스트 자료. 기준 자료 갱신 방식과 실제 API 비용 테스트 범위도 확정한다.

사진 없는 장면의 외형 검증, 직접 편집 후 근거 재검토, 직접 편집으로 타 언어가 바뀌었을 때의 적용 상태, 기존 결과와 변경 조건의 다운로드 표기, 부분 다운로드 작업 경고는 구현 전에 세부 동작을 설계한다.
